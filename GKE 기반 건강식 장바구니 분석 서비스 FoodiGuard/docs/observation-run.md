# 30시간 관측 결과

2026-09-03 09:50 ~ 09-04 16:10. 계획서 7단계(운영 증거 수집)에 해당한다.

실사용자가 없어 합성 트래픽을 흘리며 관측했다(`k8s/synthetic-traffic.yaml`). 초당 1~2건으로
낮게 잡았다. 높이면 DB 가 계속 포화돼 "평상시에 안정적인가" 를 볼 수 없다.

## 무엇이 나왔나

**30시간 동안 지연이 나빠지지 않았다.** 시간이 갈수록 느려지는 종류의 문제는 없다.

| 지표 | 최소 | 중앙 | 최대 |
|---|---|---|---|
| `/api/products` p95 | 435 ms | **450 ms** | 3,193 ms |
| `product_search_list` p95 | 201 ms | 212 ms | 2,995 ms |
| `product_search_count` p95 | 434 ms | 453 ms | 3,193 ms |
| RPS | 0.3 | 1.7 | 4.0 |

최대값의 3초대는 관측 초기 부하 테스트 구간이다. 정상 구간의 폭은 좁다.

**자원에 여유가 있다.**

| 항목 | 값 |
|---|---|
| Cloud SQL CPU | 중앙 **22%** · p95 23.5% (최대 100%는 부하 테스트 구간) |
| API 파드 메모리 | 39 Mi → 80 Mi |
| 파드 재시작 | **0회** |

메모리가 두 배가 됐지만 요청량(640 Mi)의 12% 수준이고, 30시간 동안 증가가 멈췄는지까지는
이 기간으로 판단할 수 없다. 다음 관측에서 같은 값을 다시 재 볼 항목이다.

부하 테스트 때 91~100% 였던 Cloud SQL CPU 가 실제 트래픽 수준(1.7 RPS)에서는 22% 다.
**동시 10명이 실제로 발생하지 않는 한 DB 증설은 필요 없다**는 근거가 된다.

## 관측이 잡아낸 결함

**증분 적재가 나흘째 멈춰 있었다.**

```
마지막 성공 적재   2026-08-31 11:37
확인 시점 경과     91.6 시간
누적 성공 실행     4회
경보               뜨지 않음
```

적재가 멈춰도 API 는 200 을 계속 반환한다. 지연도 오류율도 정상이다. **지표를 봐야만
드러나는 종류의 고장**이고, 실제로 아무도 모르고 있었다.

원인은 알림 정책 누락이었다. 계획서 8절이 "데이터 갱신 실패 — 마지막 성공 후 26시간 초과"
를 요구했는데 정책 일곱 개를 만들 때 빠뜨렸다. 당시에는 `foodiguard_data_last_success_
timestamp_seconds` 시계열이 없어 정책을 만들 수 없다고 판단했고, 이후 `sync_runs` 가
채워져 값이 나오게 된 뒤에도 그 판단을 갱신하지 않았다.

`data_freshness` 정책을 추가했다(`infra/gcp/terraform/monitoring.tf`). 등록 직후 조건이 참으로
평가되는 것을 확인했다.

## 준비성 프로브가 밀리는 현상

`/api/health/ready` 의 p95 최대가 **2,015 ms** 였다. 부하 구간에서 검색이 DB 커넥션을 다
물면 준비성 프로브까지 밀린다. 이 지연이 프로브 타임아웃을 넘기면 쿠버네티스가 멀쩡한
파드를 트래픽에서 빼고, 복제본이 1개라 그대로 중단이 된다.

평상시 트래픽에서는 10 ms 로 문제없다. **복제본을 2개로 늘리면 사라지는 위험**이지만,
지금 부하에서는 발생하지 않으므로 관측 항목으로만 남긴다.

## 채우지 못한 항목

| 계획서 7단계 항목 | 상태 |
|---|---|
| 대시보드 캡처 | ❌ 콘솔 로그인이 필요해 사람이 찍어야 한다 |
| Alert 발생·복구 캡처 | ⚠️ `data_freshness` 발동은 확인, 복구는 적재 재개가 선행 |
| Jenkins 자동 배포 기록 | ❌ Jenkins 가 `main` 이 아닌 다른 브랜치를 보고 있어 배포가 돌지 않음 |
| 장애 실험 결과표 | ✅ `docs/sre-validation.md` |
| 비용·성능·품질 보고서 | ✅ `docs/finops.md`, `docs/performance.md`, 이 문서 |
| 72시간 관측 | ⚠️ 30시간까지 수행 |

## 다시 돌리는 법

```bash
IMG=$(kubectl get deploy foodiguard-api -o jsonpath='{.spec.template.spec.containers[0].image}')
sed "s|BACKEND_IMAGE_PLACEHOLDER|$IMG|g" k8s/synthetic-traffic.yaml | kubectl apply -f -

kubectl delete deployment foodiguard-synthetic-traffic   # 중지
```

합성 트래픽은 실사용 패턴을 대신하지 못한다. 사용자가 실제로 무엇을 검색하는지는 여전히
모르며, `docs/performance.md` 가 보류한 검색 정렬 판단은 그 데이터가 있어야 결정된다.
